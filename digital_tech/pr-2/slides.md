## Software Engineer: роль і завдання

*Цифрові технології, практична робота 2, Лаврішко Владислав, ТЦР-32*

- Проєктує, розробляє, налагоджує та супроводжує програмне забезпечення
- Уточнює вимоги, проєктує API, пише код і автотести
- Code review, виправлення дефектів, інтеграція зовнішніх сервісів
- Керування версіями, участь у збиранні та випуску (CI/CD)
- Відповідає за якість, безпеку та результат: код, тести, документація

Приклад: застосунок прокату автомобілів (бронювання, облік, онлайн-оплата)

::: notes
Роль із методички. Наскрізна тема «Прокат автомобілів» дає конкретний контекст: платіжний шлюз, дані клієнтів, команда з кількох ролей.
:::

## Інженерна ситуація: API-ключ у відкритому репозиторії

- Ключ платіжного шлюзу випадково потрапив у коміт публічного GitHub
- Потрібні компетентності: C4.K2 захист даних, C5.K1 діагностика, C3 комунікація, C0.K3 Git
- Наслідки недостатнього рівня:
    - несанкціоновані платежі, витік даних клієнтів
    - фінансові й юридичні втрати, втрата довіри
    - видалення файлу не прибирає ключ з історії Git

::: notes
Сканери зловмисників знаходять ключі за хвилини. Тому першою дією є відкликання ключа, а не очищення коду.
:::

## Професійні дії та інструменти

1. Відкликати ключ і випустити новий (кабінет провайдера)
2. Оцінити масштаб: журнали використання, транзакції
3. Прибрати з коду: змінні середовища, GitHub Secrets / Vault
4. Очистити історію: `git filter-repo`, BFG, `git push --force`
5. Повідомити команду та відповідальних
6. Запобігти: gitleaks, pre-commit, GitHub push protection, `.gitignore`

::: notes
Порядок важливий: спочатку відкликання, потім очищення історії. Очищення історії не замінює відкликання.
:::

## Висновок

- Знання мов програмування недостатньо: потрібні безпека, співпраця, критичне оцінювання, розв'язання проблем
- Кожну компетентність пов'язано з реальним завданням, інструментом і підтвердженням (PR, CI/CD, тести, документація)
- Інцидент з ключем показує: високий рівень C4.K2 запобігає втратам, а недостатній призводить до них
- Рівень визначається самостійністю та складністю завдань, а не знанням інструмента

::: notes
Підсумок: матриця показує, що має вміти інженер ПЗ, а ситуація з ключем перевіряє це на практиці.
:::
