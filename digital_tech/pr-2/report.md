# Практична робота 2

**Тема:** «Аналіз цифрових компетентностей професійних ролей у розробці програмного забезпечення»

**Мета роботи:** Навчитися співвідносити компетентності DigCompUA з реальними завданнями, інструментами та відповідальністю фахівців, залучених до розроблення програмного забезпечення.

## Завдання

Роботу виконано індивідуально; обрано роль Software Engineer.

1. Проаналізувати роль: завдання, інструменти, ресурси, проблемні ситуації, відповідальність.
2. Побудувати матрицю не менше ніж із восьми компетентностей DigCompUA.
3. Розглянути одну інженерну ситуацію: компетентності, наслідки, дії, інструменти.
4. Підготувати презентацію на 3–5 слайдів.

## Хід виконання роботи

Приклади взято з теми «Прокат автомобілів» (застосунок із бронюванням, обліком автопарку й онлайн-оплатою).

### Завдання 3. Інженерна ситуація: API-ключ у відкритому репозиторії

Ситуація. Розробник випадково закомітив у відкритий репозиторій GitHub файл конфігурації з ключем платіжного шлюзу (умовне значення `sk_live_EXAMPLE_NOT_A_REAL_KEY`). Сканери зловмисників знаходять такі ключі за лічені хвилини.

Потрібні компетентності (рядки таблиці 2): C4.K2 (рядок 6), щоб відкликати ключ і винести секрет зі сховища коду; C5.K1 (рядок 8), щоб оцінити масштаб за журналами; C3.K3 і C3.K1 (рядки 4–5), щоб повідомити команду й узгодити `git push --force`; C0.K3 (рядок 1) для `git filter-repo` і gitleaks у CI; C4.K1 (рядок 7) для 2FA на акаунті, з якого стався витік.

Наслідки недостатнього рівня. Несанкціоноване використання ключа (платежі від імені компанії, доступ до даних клієнтів); фінансові й юридичні втрати за порушення захисту персональних даних; втрата довіри клієнтів. Видалення файлу лише з останнього коміту лишає ключ в історії, а без відкликання він чинний; без автоматичних перевірок інцидент повториться.

Професійні дії та інструменти:

1. Відкликати ключ і випустити новий (кабінет провайдера).
2. Оцінити масштаб: журнали й транзакції від моменту публікації (журнали провайдера).
3. Винести ключ у змінну середовища або сховище секретів (GitHub Secrets, Vault, `.env` у `.gitignore`).
4. Видалити ключ з історії й оновити віддалений репозиторій (`git filter-repo`, BFG, `git push --force`).
5. Повідомити команду й відповідальних, за потреби клієнтів (Jira, месенджер).
6. Запобігти повторенню: gitleaks у pre-commit і CI, GitHub push protection; провести ретроспективу.
