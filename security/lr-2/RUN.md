# ЛР 2: запуск і показ

Потрібен лише Docker. Усі команди з теки `security/lr-2`. Перевірки виконує Python у контейнері `python:3.12-slim`; вони лише читають файли й нічого не записують. Реєстр загроз береться з сусідньої теки `../lr-1/model/threats.md`.

Працювати з ASVS онлайн не потрібно: вимоги складено за текстом ASVS 5.0.0 заздалегідь, у цій теці лежать готові `requirements.md` і `report.md`. Звірку кожного ID з файлом стандарту виконано під час підготовки, `make` її не повторює, а перевіряє внутрішню узгодженість і покриття загроз.

## Пайплайн

```sh
cd security/lr-2   # шлях відносно кореня репозиторію
make numbers    # скільки вимог, ID і яких типів
make rule       # правило поділу на обов'язкові й рекомендовані
make coverage   # кожна загроза з ЛР 1 має вимогу
make report     # таблиця розділу 4 звіту проти requirements.md
make element E=P-3   # вимоги одного елемента (EI-1, EI-4, P-4, DS-1, F9 тощо; для потоків і спільних розділів шукається код у заголовку)
make open       # відкрити report.pdf і схему архітектури
```

`make show` виконує перші чотири по черзі, `make help` показує цілі.

## Кроки

- `make numbers`, `rule`, `coverage`, `report`: `python -I scripts/check_requirements.py <частина>` читає `requirements.md`, `report.md` і `../lr-1/model/threats.md`.
- `numbers` рахує рядки таблиць за елементами й потоками, різні ID, типи (обов'язкова, етап 2, етап 3) і вимоги L1, які не застосовано.
- `rule` перевіряє правило поділу: усі L1 обов'язкові, жодна L3 не обов'язкова, обов'язкова L2 завжди закриває загрозу високого ризику.
- `coverage` звіряє T01-T29 із реєстром ЛР 1: кожна загроза має вимогу, кожна з 11 високих має обов'язкову, рівні ризику збігаються, усі ID з трасування є в таблицях.
- `report` порівнює числа таблиці розділу 4 звіту з підрахунком за `requirements.md` для кожного елемента.

## Що показати

1. `make numbers`: `рядків (пар елемент і вимога): 208`, `різних ID ASVS: 133`, `обов'язкових / етап 2 / етап 3: 101 / 95 / 12`, `вимог L1 не застосовано (з 70): 14`, `різних вимог L1 застосовано: 56`.
2. `make rule`: три порожні списки винятків: `L1, які не обов'язкові: []`, `L3, які обов'язкові: []`, `обов'язкові L2 без високої загрози (В): []`.
3. `make coverage`: `загроз у реєстрі ЛР 1: 29`, `загроз у трасуванні: 29`, `загроз високого ризику: 11`, `високі без обов'язкової вимоги: []`, далі обов'язкові вимоги для T01, T02, T04, T05, T08, T11, T14, T15, T16, T18, T28 (наприклад, `T05: 1.2.4, 2.2.1`).
4. `make report`: рядки всіх елементів, наприкінці `Усього: 101 / 95 / 12 / 208` без позначок розбіжності, потім `Перевірку пройдено.`

## Звідки що береться

- `requirements.md`: повний перелік вимог за елементами й потоками, трасування від загроз і вимоги L1, які не застосовано.
- `report.md`: звіт; таблиці розділів 3 і 4 зведені з `requirements.md`.
- `img/dfd.png`: схема архітектури, скопійована з ЛР 1.
- `../lr-1/model/threats.md`: реєстр загроз T01-T29 з ризиками.
