# 1. Тема та мета роботи

**Тема:** «SAST, SCA інструменти».

**Мета роботи:** ознайомитись зі сканерами SAST і SCA на власному коді й оцінити знайдене за CVSS («самостійно ознайомитись з SAST/SCA сканерами за допомогою відкритої версії Semgrep»). Скановано ЛР 3 (Boot 3.3.5, у профілі `vuln` навмисно вразливе демо) і ЛР 6 (Boot 3.5.16). Код і результати: [репозиторій](https://github.com/brizzinck/krinzhrepoduta/tree/main/security/pr-7).

# 2. Короткі теоретичні відомості

SAST аналізує код, не запускаючи його: потоки керування й даних, шлях недовірених даних до небезпечного виклику (taint). Контексту він не знає, тому дає хибні спрацювання. SCA звіряє залежності, прямі й транзитивні, з CVE, NVD, GHSA; вразливості, якої ще немає в базі, не бачить. DAST перевіряє запущений застосунок ззовні. CVSS v3.1 має вісім базових метрик; рівні: 0,0 None, 0,1-3,9 Low, 4,0-6,9 Medium, 7,0-8,9 High, 9,0-10,0 Critical.

# 6. Оцінка за CVSS v3.1

Таблиця 4. Базові метрики SQL-ін'єкції `VulnerableDemoController.java:43`; вектор `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:L` дає 8,2 (High)

| Метрика | Значення | Чому |
|----------------|-------------|----------------------------------|
| AV, вектор | N, мережа | `/demo/vuln/search` доступний по HTTP |
| AC, складність | L, низька | достатньо одного запиту, умов немає |
| PR, привілеї | N, не потрібні | вхід не вимагається |
| UI, дія користувача | N, не потрібна | жертва не бере участі |
| S, область дії | U, без зміни | вражається лише БД застосунку |
| C, конфіденційність | H, висока | через `UNION` читаються всі таблиці |
| I, цілісність | N, немає | `queryForList` виконує один `SELECT` |
| A, доступність | L, низька | важкий запит чи `SLEEP` сповільнить БД |

# 8. Висновки

Semgrep CE дав 7 спрацювань: 4 істинні (SQL-конкатенація в `vuln`) і 3 хибні (BCrypt-хеші). `th:utext` і пароль БД він пропустив: правила на `th:utext` у наборах немає, а `p/secrets` шукає формати токенів, не звичайний пароль. Trivy: 89 вразливостей (15 Critical) у ЛР 3 і 21 у ЛР 6, головно Tomcat і Jackson. За CVSS `search`-ін'єкція спала з 8,2 до 5,4, а три Critical і один High стали 0,0, бо код не використовує вразливу можливість. Після оновлення лишилось по дві знахідки, їх закриє лише Boot 4.
