# 1. Мета роботи

Записати поведінку лямбда-виразами й посиланнями на методи, обробити колекцію через Stream API, побачити лінивість потоку й перевірити, як Optional описує результат, якого може не бути.

# 2. Завдання за варіантом

Номер у списку групи 12, варіант 2 (12 mod 5): клас `Issue` (ключ, назва, story points) із ПР 6, без `equals` і `hashCode`. Сортування за story points. Обчислити суму story points задач з оцінкою не менше 5. Пошук без результату: задача з оцінкою понад 100. У списку 9 задач, оцінки 1, 2, 3, 3, 5, 5, 8, 8, 13: п'ять з них (5, 5, 8, 8, 13) відповідають умові «не менше 5». Maven, Java 21, запуск у docker. Повні виводи в `results/`.

# 3. Дослід 1. Три способи сортування

Той самий список відсортовано анонімним класом, лямбдою й посиланням на метод:

```java
byAnonymous.sort(new Comparator<Issue>() {
    @Override
    public int compare(Issue a, Issue b) {
        return Integer.compare(a.getStoryPoints(), b.getStoryPoints());
    }
});
byLambda.sort((a, b) -> Integer.compare(a.getStoryPoints(), b.getStoryPoints()));
byReference.sort(Comparator.comparingInt(Issue::getStoryPoints));
```

Після кожного сортування програма друкує список (`results/exp1_sort.txt`). Усі три списки однакові, навіть для рівних оцінок (сортування стабільне), програма це перевіряє:

```
> java … Exp1Sort

  SHOP-107 (1 SP) Міграція таблиці users
  SHOP-105 (2 SP) Кешування каталогу
  SHOP-103 (3 SP) Темна тема інтерфейсу
  SHOP-109 (3 SP) Docker-образ для сервісу
  SHOP-101 (5 SP) Вхід через Google
  …
  SHOP-104 (13 SP) Пагінація в пошуку
Лямбда-вираз (9 рядків):
  …
Comparator.comparingInt (9 рядків):
  …
Порядок збігається: true
```

Анонімний клас займає 6 рядків, лямбда й `comparingInt` по одному. Лямбда прибирає службовий код (`new Comparator`, `@Override`, сигнатуру), а посилання на метод ще й не повторює порівняння, а лише називає поле.

Потім я спробував порахувати порівняння, збільшуючи `int calls = 0;` у лямбді:

```
> javac … compile-errors/E1_calls/*.java
CallsError.java:11: error: local variables referenced from a lambda expression must be final or effectively final
            calls++;   // спроба порахувати порівняння
```

Лямбда може пережити метод, у якому створена, і виконатися пізніше чи в іншому потоці, тому вона працює з копією значення локальної змінної. Якби змінну можна було змінювати, копія й оригінал розійшлися б. Тому компілятор вимагає, щоб змінна не змінювалась після ініціалізації (effectively final).

# 4. Дослід 2. Цикл проти потоку, лінивість

Сума story points задач з оцінкою не менше 5 двома способами:

```java
for (Issue issue : issues) {
    if (issue.getStoryPoints() >= 5) {
        sum += issue.getStoryPoints();
    }
}

return issues.stream()
        .filter(issue -> issue.getStoryPoints() >= 5)
        .mapToInt(Issue::getStoryPoints)
        .sum();
```

```
> java … Exp2Sum
цикл: 39   потік: 39
```

Результати збіглися: 5 + 8 + 13 + 5 + 8 = 39.

Далі в конвеєр доданий `peek` з друком ключа. Перший запуск із термінальною операцією `sum()`, другий із конвеєром, збереженим у змінну `Stream<Issue>` без термінальної операції:

```
> java … Exp2Peek terminal
peek SHOP-101
peek SHOP-102
peek SHOP-104
peek SHOP-106
peek SHOP-108
сума: 39

> java … Exp2Peek lazy
Конвеєр створено, термінальної операції немає
```

Проміжні операції `filter`, `peek`, `mapToInt` лише описують конвеєр і нічого не виконують. Робота починається, коли викликають термінальну операцію. У першому запуску `peek` надрукував 5 рядків, по одному на задачу, що пройшла `filter`, а в другому не надрукував нічого, бо термінальної операції не було.

# 5. Дослід 3. Optional

Пошук задачі з оцінкою понад 100 (такої немає) і за умовою досліду 2 (не менше 5):

```java
Optional<Issue> none = issues.stream().filter(i -> i.getStoryPoints() > 100).findFirst();
System.out.println("  map(Issue::getKey).orElse: "
                + none.map(Issue::getKey).orElse("не знайдено"));
```

```
> java … Exp3Optional

  Optional: Optional.empty
  isPresent: false
  map(Issue::getKey).orElse: не знайдено
Пошук за умовою досліду 2 (оцінка не менше 5):

  isPresent: true

Виклик `get()` на порожньому Optional (окремий запуск, виняток не перехоплено):

```
> java … Exp3Get
Exception in thread "main" java.util.NoSuchElementException: No value present
	at java.base/java.util.Optional.get(Optional.java:143)
	at ua.duikt.lavrishko.pr7.Exp3Get.main(Exp3Get.java:11)

`orElse` і `map` обробляють обидва випадки без винятку: для порожнього результату дають запасне значення, для наявного ключ першої знайденої задачі. `get()` без перевірки `isPresent()` падає на порожньому Optional, і програма завершується з кодом 1.

# 6. Відповіді на контрольні питання

**1. Чим лямбда-вираз відрізняється від анонімного класу?** Лямбда реалізує функціональний інтерфейс (з одним абстрактним методом) коротким записом і не створює окремого класу з власним `this`. Анонімний клас може реалізувати й інтерфейс із кількома методами, мати поля й власне `this`. У досліді 1 те саме порівняння це 6 рядків проти одного.

**2. Що означає «фактично незмінна» змінна і навіщо обмеження?** Локальна змінна, значення якої не змінюється після ініціалізації (не обов'язково з `final`). Лямбда копіює її значення, а змінна зникає разом із методом, тому змінювати її з лямбди заборонено. Це дало помилку компіляції для `calls++`.

**3. Чим проміжна операція потоку відрізняється від термінальної?** Проміжна (`filter`, `map`, `peek`) повертає новий потік і лише додає крок у конвеєр, нічого не виконуючи. Термінальна (`sum`, `toList`, `findFirst`) запускає конвеєр і дає результат. Без неї `peek` нічого не надрукував.

**4. Чому `findFirst` повертає Optional і чим `orElse` кращий за `get()`?** Результату може не бути, і Optional змушує це врахувати замість `null`. `orElse` задає запасне значення, тому програма працює в обох випадках, а `get()` на порожньому Optional кидає `NoSuchElementException`.

# 7. Висновки

Сортування анонімним класом, лямбдою й `Comparator.comparingInt` дало однаковий порядок 9 задач, але запис скоротився з 6 рядків до одного. Спроба збільшувати `calls` у лямбді не скомпілювалась, бо локальна змінна має бути фактично незмінною. Цикл і потік дали ту саму суму 39 для задач з оцінкою не менше 5. `peek` надрукував п'ять ключів лише тоді, коли конвеєр завершувала термінальна операція `sum()`, а без неї нічого. Пошук задачі понад 100 SP повернув `Optional.empty`, `get()` на ньому кинув `NoSuchElementException`, а `map(...).orElse("не знайдено")` обробив обидва випадки без винятку.
